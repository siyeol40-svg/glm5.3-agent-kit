# 기존 AGENTS.md / Skill 마이그레이션

**백업 → 자동 로딩 해제 → 충돌 검사 → 새 Kit 적용 → 테스트 → 기존 파일 삭제 여부 결정** 순서입니다. 즉시 삭제하지 않습니다. PPT Master는 유지합니다.

## 1. 실제 로딩 위치 확인

실행기 설정과 작업 루트/상위 경로/사용자 범위에서 자동 로딩하는 AGENTS.md와 SKILL.md 위치를 확인합니다. 도구의 실제 로딩 기록과 비교합니다. 파일이 존재하는 것과 로딩된 것은 다릅니다. 회사 시스템에 특정 탐지 명령이 있다고 가정하지 않습니다.

## 2. 목록 작성과 백업

회사 로컬에 `원래 경로 / 역할 / 자동 로딩 여부 / 사내 전용 명령 / 백업 위치 / 파일 해시 / 처리 결정` 표를 만듭니다. 사내 명령·필수 준수 규칙을 먼저 읽습니다. 파일과 폴더 전체를 버전이 표시된 회사 허용 백업 위치로 복사하고 파일 수·해시를 확인합니다. 백업·목록은 공개 repo에 올리지 않습니다.

## 3. 중복 지침 자동 로딩 해제

새 Skill과 역할이 겹치는 커스텀 PPT 규칙만 비활성화합니다. 실행기가 제공하는 disable 기능을 우선 사용합니다. 없다면 **실제로 스캔되지 않는 경로**로 옮긴 후 로그로 확인합니다. 이름에 `.bak`를 붙이거나 검색 폴더 안의 backup 하위 폴더로 옮기는 것만으로는 자동 로딩이 해제된다고 보장할 수 없습니다.

PPT Master 실행 엔진은 제거하거나 비활성화하지 않습니다. 회사 전용 접근 명령과 보안 규칙은 회사 로컬 overlay에 보존합니다. 이 Kit으로 덮어쓰지 않습니다.

## 4. 충돌 검사

다음을 대조하여 한 역할에 하나의 권위만 남깁니다.

| 충돌 | 해결 |
|---|---|
| 기존 전역 지침의 자유로운 재디자인 | 프로젝트의 디자인 보존 요구와 상위 Skill로 제한 |
| Generate 기본값 강제 | 원본 유지 작업에는 Edit Native 경로 지정 |
| 엔진 backing/XML 직접 편집 | 금지, roundtrip exporter 사용 |
| 렌더 완료=검증 통과 | 상태 분리, 지역 QA 필수 |
| 한국어/존댓말 상충 | 전역 언어 규칙 통일 |
| 사내 필수 실행 명령 | 회사 로컬 overlay에 유지 |

정확한 로딩 우선순위는 실행기에 따릅니다. 이 저장소의 순서가 실제 시스템 우선순위를 자동 변경하지는 않습니다.

## 5. 새 Kit 적용과 실제 로딩 확인

AGENTS.md와 Skill 폴더 전체를 적용합니다. AGENTS만 붙여넣거나 SKILL.md만 복사하지 않습니다. 에이전트에게 실제 로딩 파일·Skill·엔진 경로를 확인하게 하고 로그와 대조합니다. 경로를 보여주지 않는 실행기라면 구체적인 회귀 작업으로 규칙이 적용되는지 확인합니다. 단순히 “읽었습니다”라는 대답만으로 적용을 확정하지 않습니다.

## 6. 테스트와 삭제 결정

합성 자동 테스트 → 원본 보존 편집 → 미검토 QA 차단 → 누락된 이미지/그룹 텍스트 차단 → 후보 수정 후 오래된 영수증 차단 순으로 확인합니다. 실제 업무 자료의 반출 없이 회사 로컬에서 시행합니다.

문제가 없을 때만 구 파일의 장기 보관/삭제를 결정합니다. 삭제가 필수는 아닙니다. 필요 규칙이 발견되면 백업에서 복구하고 충돌을 재검사합니다. 롤백은 새 Kit 비활성화 → 이전 파일 원래 위치 복원 → 실제 로딩 확인 → 테스트 순서로 진행합니다.

## v0.2 자동 적용

루트 README의 bootstrap-plan.json을 관측된 경로/원본 해시와 검토된 로컬 overlay로 채운 뒤 scripts/bootstrap.py check/apply/verify를 수행합니다. 원본 전체를 먼저 백업·검증한 후 로딩 위치의 중복 Skill을 제거하고 Kit Skill을 복사합니다. AGENTS 파일도 사내 필수 규칙을 보존한 새 내용으로 교체합니다. 기본 파일은 AGENTS.md이며 실제 실행기가 agent.md 같은 다른 이름을 읽는 경우 정확한 기존 경로를 계획에 넣습니다.

읽기 전용 Kit checkout 안의 파일을 회사에서 고치지 않습니다. 비활성화는 별도 백업으로 이동해 자동 스캔 대상에서 제거하는 것이며 폐기가 아닙니다. 경로 확인·충돌 해결을 에이전트가 수행하므로 임의 경로를 추정해 스크립트에 넣지 않습니다. verify는 파일 상태 확인이며 실제 에이전트의 활성 지침 로딩은 instruction_loading.json으로 별도 확인합니다.
