# 회사 read-only 적용

개인 환경에서 이 GitHub 저장소를 관리하고 회사에서는 승인된 계정·읽기 경로로 내려받기만 합니다. 개인 GitHub 로그인이나 쓰기 자격증명을 회사에 넣지 않습니다.

1. [마이그레이션](migration-guide.md)을 먼저 수행합니다.
2. 회사에서 허용한 다운로드/clone 방식으로 **검증된 commit**을 확보합니다. 저장소를 읽을 수 있다는 사실만으로 Skill 자동 로딩이 되는 것은 아닙니다.
3. 실행기의 실제 AGENTS/Skill 검색 위치를 확인합니다. 프로젝트 범위라면 AGENTS.md와 `.agents/skills/ppt-reference-fidelity/`를 적용합니다. 해당 경로를 지원하지 않는 실행기는 승인된 Skill 위치에 폴더 전체를 배치하고 실제 탐지를 확인합니다. 사내 전용 규칙은 회사 로컬 overlay로 유지합니다.
4. 기존 PPT Master는 별도 설치 상태로 유지합니다. 실행기의 탐지 결과에 두 Skill의 정확한 이름·경로가 표시되는지 확인합니다.
5. Python 3.10+에서 `python -m unittest discover -s tests/ppt-reference-fidelity -v`를 실행합니다. 핵심 검사는 표준 라이브러리만 필요합니다. Pillow가 없으면 이미지 테스트는 skip되므로 이미지 QA 준비 완료로 보고하지 않습니다.
6. 실제 PPT Master 경로로 preflight를 실행합니다. 회사 실행기 명령·모델 alias·권한·이미지 MCP를 실제로 확인합니다.
7. 공개 저장소와 분리된 회사 허용 로컬 작업 폴더에서만 업무 파일과 증거를 생성합니다. 공식 GitHub repo에는 push하지 않습니다.
8. 먼저 합성 PPT와 명백히 잘린 제목 이미지로 차단 테스트를 합니다. 회사 업무 자료는 여기에 저장하지 않습니다.

## 업데이트와 롤백

업데이트 전 Kit commit, PPT Master 버전/해시, 활성 지침 목록을 기록합니다. 새 Kit을 별도 폴더에서 검사한 뒤 교체합니다. 테스트 실패 시 이전에 검증한 버전과 백업 지침으로 복원합니다. 원격 main이 바뀌었다는 이유로 진행 중인 작업의 규칙을 바꾸지 않습니다.

인증정보나 사내 주소를 설정 예시로 커밋하지 않습니다. `.gitignore`는 보조 장치이며 비밀 탐지기나 업로드 허가가 아닙니다. 필요한 새 규칙은 개인 환경에서 일반화하여 Kit에 반영합니다.
