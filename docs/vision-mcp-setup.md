# v0.3 현재 QA 기준

모든 시각 QA는 사용자가 제공한 캡처만 입력합니다. look_at/looker가 이미지를 실제 처리했는지 확인하되, 결함을 인지하지 못하면 최종 판정 역할에서 제외하고 사용자 피드백/수용을 기준으로 합니다. 자세한 계약은 설치된 Skill의 references/user-capture-qa.md와 com-workflow.md를 읽으십시오. 아래 v0.2의 자동 렌더/pixel 관련 권고는 DRM 프로필에 적용하지 않습니다.

# 현재 이미지 분석 도구와 역할

## 확인된 정보와 미확인 정보

사용자가 확인한 실행기 기능:

- `look_at`: GLM-5.3이 호출하고 이미지 해석 결과를 텍스트로 받음.
- `call_omo_agent(subagent_type="multimodal-looker")`: 서브에이전트가 해석 후 텍스트/JSON 형식으로 보고.
- 두 경로는 로컬 파일 경로 또는 base64(image_data)를 지원한다고 보고됨.
- 별도의 MCP 기반 사내 Vision 서버는 없음.
- 실행기 전체 컨텍스트 한도는 200,000토큰이라고 보고됨.

이 개발 환경에서는 해당 사내 도구를 실제 호출하지 못했습니다. 실제 매개변수 이름·이미지 전처리·토큰 계산·남은 컨텍스트 계측·도구별 제한을 실행 환경에서 확인해야 합니다. 도구 이름만으로 내부 추론 모델이나 네트워크 경로를 단정하지 않습니다. 로컬 파일 경로 입력은 “로컬 추론” 또는 “이미지 컨텍스트 소모 없음”을 뜻하지 않습니다.

## v0.2 역할 제한

핵심 검증은 PPTX 객체/내용 비교, 실제 PowerPoint 텍스트 측정, 같은 환경 렌더의 사전 mask 밖 픽셀 비교입니다. 이미지 도구는 사진의 의미, 가림, 정성적 구조 차이 등 남은 질문의 보조 수단입니다. 보고를 JSON으로 받는다고 분석의 정확성이 보장되지는 않습니다.

관련 결함 영역만 조회하고 짧은 발견 보고를 받습니다. full preview에서는 전체 배치/위계만 봅니다. 제목 끝 글자·crop·그림자 등은 적절한 상세 크기로 확인합니다. 1920×1080 원본 두 장을 매번 함께 호출하는 방식을 기본값으로 고정하지 않습니다. 실제 오류가 없다면 해상도만으로 무조건 불가능하다고 말하지도 않습니다.

200,000토큰은 시스템/대화/지침/도구/이미지와 출력 예약을 관리할 예산이며, 개별 이미지 도구의 한도를 보장하지 않습니다. 실제 사용량 계측이 있을 때만 비율을 계산합니다. 없으면 “미계측”으로 남깁니다. raw XML·base64·반복 보고는 로컬에 보관하고 필요한 결과만 주 실행기에 전달합니다.

## 보고 기록

실제 tool schema를 읽고 호출합니다. 로컬 request/입력 파일 해시, 호출 ID, raw 보고서, 검토 항목을 보존합니다. visual_review.py는 입력 준비와 엄격한 JSON 텍스트 보고 기록을 도와주며 실제 도구 client는 아닙니다. 원문 자연어를 모든 항목 PASS로 임의 바꾸지 않습니다. 판독 불가·실행 오류·미확인은 NOT REVIEWED입니다.

구조·layout·pixel 중 하나라도 실패하면 비전 보고만으로 최종본을 선언할 수 없습니다. 지원하지 않는 native geometry는 별도 검증이 구현되기 전 strict 완료를 차단합니다. 사람의 잔여 영역 검토도 가능하지만 수행하지 않은 검토는 통과가 아닙니다.

## 외부 서비스 경계

현재 Z.ai 외부 서비스는 대상 네트워크에서 차단된 것으로 보고되어 기본 연결로 사용하지 않습니다. API·MCP를 바꾸어 같은 차단 endpoint를 재호출하는 것으로 해결된다고 가정하지 않습니다. 프록시/WAF를 우회하거나 별도 사내 서버 설치를 요구하지 않습니다. 공개 저장소에는 회사 API 주소·인증정보·도구 원문 업무 보고를 저장하지 않습니다.
