# 제안 작성 · 고정 프로필

사용자의 짧은 요청과 자료로 필요한 질문만 묶습니다. 사용자에게 JSON·제작 코드를 요구하지 않습니다. 모델은 내용·허용 구성 선택을 맡고 도구는 원장 치환·배치·COM 제작·검사를 담당합니다. 코드 전체를 읽거나 새 제작 코드를 작성하지 않습니다.

## 필요한 단계 하나만 읽기
처음에는 [회사 규칙](references/company-rules.md)과 [자료 확인](references/00-intake.md)만 읽습니다. 최초 Case를 만들 때만 [최소 입력](references/v4/input.md)을 추가로 읽습니다. 이후 도구의 `context`가 지정한 현재 단계와 그 자료만 읽고, 아래 진입 파일이 연결한 leaf 하나를 선택합니다. 미래 leaf·완성 예시·전체 소스·전체 이력을 펼치지 않습니다.

새 제안은 문제 현상 `reference-v5-problem`을 사용하며, 개선 사항은 근거로 조치 여섯 개를 두 역할로 묶을 수 있으면 V10, 그 외에는 넓은 3×2 카드 V8의 지원 범위를 확인합니다. 원인 분석·효과 파악·횡전개는 [V7 공통 규칙](references/v7/common.md)의 검증된 의미별 표현을 먼저 검토합니다. 해당 기전·지표·계획 구조와 근거가 맞을 때만 `reference-v7`을 선택합니다. 다른 설비의 근거 연결, 단일 배수, 동일 기준의 시점별 비교는 현재 단계의 V9를 검토합니다. 지원 구조가 다르면 V6 범위를 확인합니다. 자료가 부족하면 필요한 근거를 묻습니다. 기존 실행은 `context`의 profile과 해당 규약을 유지합니다.

## 회사 표기
[English 용어·수식어·한국어 설명](references/terminology.md)을 따릅니다. 표·카드·숫자 원장의 지표명을 함께 맞추고 실제 수치·조건·출처는 바꾸지 않습니다. 영어 형용사·수식어도 개수 제한 없이 사용합니다. 고정 페이지 이름은 유지합니다.

## 작업 흐름
먼저 [필수 분량 합격선](references/content-density.md)을 확인합니다. 낮은 분량은 기존 COM/디자인 평가나 과거 완료 상태로 통과할 수 없습니다. 모든 단계에 필수이며 정책값을 작성자가 낮추지 않습니다.
1. 출처·수치와 필요시 식별자 원장으로 `Invoke-Proposal.ps1 -Action init`을 실행합니다. 미래 단계는 비어 있어도 됩니다. 기존 실행은 `status`/`context`로 재개합니다.
2. 현재 단계 leaf가 연결한 V5/V6/V7/V8/V9/V10 빈 틀 하나를 채웁니다. 사실 ID가 있는 [문제 현상 절차형](references/v5/procedure-brief.md)은 작성 JSON을 만든 뒤 `prepare-problem`으로 빈 단계 파일을 채웁니다. 그 외에는 `stages/<id>.json`에 작성합니다. 수치는 `[[N1]]`, 등록된 설비명은 `[[I1]]`로 연결합니다. V7/V9/V10의 `visuals`는 의미와 문구의 연결을 지정하며 좌표를 받지 않습니다. 빈 mapping의 `null`은 미지정이므로 현재 문구에 맞는 정수로 채웁니다. 동결된 스킬/배치/코드를 사례별로 수정하지 않습니다.
3. `validate`에서 근거·기하·분량 하한을 모두 확인한 뒤 지정된 열린 작업 문서에 `render`를 실행합니다. 도구가 실제 COM 객체와 분량을 검사하고 상태를 기록합니다. 미달이면 완료 상태를 만들지 않습니다.
4. 실패·확인불가는 원인과 상태를 남기고 다음 단계를 중단합니다. 현재 COM 측정으로 확인된 기존 객체의 허용된 복원만 [제자리 수정](references/repair.md)으로 처리합니다. 별도 시각 검수 답을 받아 고치거나 근거 없이 재시도하지 않습니다.
5. 마지막 단계 후 전체 검사와 명시된 경로의 저장을 수행합니다. 구조 검사, 실제 화면 검사, GLM 사용 성공, 회사 호환 성공은 별개로 보고합니다.

도구는 이 스킬의 `scripts/Invoke-Proposal.ps1`입니다. `-RunDir`는 허용된 실행 기록 폴더, `-StageId`는 현재 단계, `-TargetName`은 이미 열린 지정 작업 문서입니다. 후속 답변은 [원장 추가](references/v4/ledger-update.md)로 처리합니다.

내용 과다는 의미를 유지해 단축합니다. 분할은 도구가 실제 지원하는 경우만 사용하고, 지원하지 않으면 필요한 범위를 확인하며 새 좌표/코드를 즉석 생성하지 않습니다.

자료가 부족하면 필요한 근거를 묻고 미완료로 남깁니다. 최소 분량은 문제18/원인15/개선18/효과15/횡전개21항목이며, 간결형이나 제목·반복 문구로 우회하지 않습니다. V7은 제한된 구성의 지원이며 전체 입력·GLM 실사용·회사 호환을 보증하지 않습니다. 디자인98점은 개발 목표이고 달성 사실로 보고하지 않습니다.

페이지 제목은 업무의 핵심 주장으로, 소제목은 짧은 명사구로 씁니다. 자료 상태나 제작 과정에 관한 말로 지면을 채우지 않습니다. 조치의 outcome은 본문을 반복하지 않고 목적을 짧게 적습니다. 도해는 설비·부품·현상에 맞게 선택하며 실제 사진이나 측정 근거로 주장하지 않습니다.

제작·검사 성공은 실제 기록으로만 보고합니다. 회사 실행에서는 자동 캡처·이미지/PDF export·화면 렌더·look_at·Office 직접 파싱 없이 확인할 수 있는 범위만 결과로 남깁니다.

사진은 지정된 동일 열린 작업 문서의 기존 COM 객체만 참조합니다. 가상 시험 이미지는 실제 사례 근거와 분리해 표시하며, 기술 효과만 있을 때 금액·비용 합계를 만들지 않습니다.

원시 디자인 참고 이미지·QA 이미지/렌더/캡처·검수 메모·오류 위치/수정 답은 제작 입력에서 제외합니다. 업무 PPT에도 검수 점수·오류 의견을 넣지 않습니다. 최종 답변 뒤 별도 평가하며, 실패 수정본을 첫 실행 통과로 세지 않습니다.

지원하지 않는 구조나 자료 부족은 멈추고 필요한 자료와 한계를 짧게 보고합니다.
