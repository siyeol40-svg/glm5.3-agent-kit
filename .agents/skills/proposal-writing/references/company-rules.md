# 회사 적용 공통 규칙

이 규칙은 회사 배포 스킬의 실행 경로에 적용합니다. Codex 개인 공개 예시의 개발 시각 검수는 별도 사용자 승인 범위이며 회사 실행 기능이 아닙니다. 전체 DLP·실행기·폰트까지 동일하게 재현한 것은 아닙니다.

**단계는 분리합니다.** Codex의 틀 개발 → 스킬/라이브러리 동결 후 새 사례 제작 → 작성자 최종 답변 뒤 별도 평가 순서입니다. 제작 중에는 고정된 소스 해시를 유지하고 사례에 맞춰 배치·코드를 수정하지 않습니다. 개발 시각 QA는 회사 제작의 필수 기능이 아닙니다.

제작자에게는 업무 사실, 허용된 원본 사진/동일 문서 COM 자산 참조, 고정된 승인 스킬·라이브러리, 현재 단계 지침, 허용 COM 측정값만 전달합니다. **원시 디자인 참고 이미지·QA용 PNG·출력 렌더·캡처, 시각 검수 메모, 오류 위치·수정 정답은 전달하지 않습니다.** 정상 업무 원본 이미지와 개발/결과 검수 이미지를 구분합니다. 별도 시험에서 JSON만 허용하면 원본 이미지도 그 시험에는 넣지 않습니다.

업무 PPT에는 시각 QA 보고·점수·오류 의견을 넣지 않습니다. ‘공급사 발표·개념도·검토안’처럼 주장 성격과 근거를 알리는 표시는 업무 내용이므로 유지합니다.

최종 답변 뒤 평가 결과는 별도 기록합니다. 실패를 검수 정답으로 고쳐 첫 실행 통과로 바꾸지 않습니다. 수정은 다음 틀 개발 revision에서 하고 새 동결·새 독립 시험으로 확인합니다. Codex 개인 시험, GLM 실제 사용, 회사 호환 성공을 따로 보고합니다.

- 기존·새 파일·복사본·저장물도 DLP 대상입니다. 보호 Office 파일의 직접 읽기·ZIP/XML·bytes/hash·해제는 사용하지 않습니다.
- 회사 PPT는 사용자가 정상 PowerPoint에서 열어 둔 지정 문서에 active COM으로 연결합니다. 새 앱 인스턴스·자동 Open·자동 재열기·다른 문서 종료를 사용하지 않습니다. 개인 공개자료 시험용 새 빈 문서 추가는 별도 사용자 승인 범위입니다.
- 처음 연결할 조건이 불명확할 때 [COM 확인 범위](com-check.md)를 읽습니다. 매 제작·검사마다 사전 점검을 반복하지 않습니다.
- 자동 캡처·이미지/PDF export·렌더·look_at을 PPT QA에 쓰지 않습니다. 수동 캡처를 필수 단계로 추가하여 무인 자동화가 된 것으로 보고하지 않습니다.
- 수동 캡처를 제공해도 회사 모델의 정밀 시각 판독 품질을 신뢰할 수 있다는 전제를 두지 않습니다. 회사 실행은 검증한 고정 틀·허용 변형·COM 검사에 한정하며 미지원은 멈춥니다. Codex 개발 시각 검수 통과를 회사의 시각 검수 능력으로 보고하지 않습니다.
- 새 API/키/엔드포인트/MCP/서버/설치를 요구하지 않습니다. 코드·JSON·로그의 회사 읽기/쓰기 가능 여부는 별도 확인합니다. 실패하면 평문 우회 파일을 만들지 않습니다.
- 원본 사진·사건·실적을 디자인 예시에서 새 제안의 근거로 가져오지 않습니다. 공개 시험에는 공개 자료만 사용합니다. 회사 자료는 외부 모델/공개 저장소로 보내지 않습니다.
- COM 조회 성공은 실제 화면 품질의 합격이 아닙니다. 회전·자동맞춤·그룹 변환은 관측 범위를 확인합니다. 읽힌 최소 글자 크기 위반은 별도 실패로 다룹니다. 생성물은 회전과 자동축소를 기본 금지합니다.
- 저장 성공·현재 객체 재조회·사용자 UI 재열기를 구분합니다. 프로그램 종료코드, 원문/좌표 검사, 미학 판단을 하나로 합치지 않습니다.

각 결과에는 작성 주체와 실제 실행·검증·미확인을 기록합니다. 회사 호환성은 회사 안의 시험 전까지 미검증입니다.
