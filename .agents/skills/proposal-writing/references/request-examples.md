# 짧은 요청과 새 세션 인계

아래는 사용법 설명이며 실행 실적이 아닙니다. JSON은 모델이 준비하고 사용자는 평소 업무 말투로 요청합니다.

## 공개 사례로 시작

> 공개된 드라이 펌프 절전 사례로 제안서 만들어줘. 타 설비에 적용한 실적은 없어.

선택한 공개 사례 자료만 확인합니다. 공급사가 발표한 펌프 소비전력과 공장 전체 에너지를 구분해 원장에 등록합니다. 모든 단계 ID를 준비한 뒤 현재 문제 현상부터 채웁니다. 횡전개는 실적 대신 검토안으로 남깁니다. 도구가 원문을 자동 검증하거나 미공개 금액을 계산해 주는 것은 아닙니다.

## 자료가 적을 때 시작

> 열교환기 세척이 자주 필요하다는 공개 기록으로 문제 현상부터 만들어줘. 횟수와 사진은 없어.

확보된 현상·영향·자료 범위로 사진 없는 고정 틀을 선택합니다. 횟수와 사진을 지어내지 않고 자료 부족을 표시합니다. 추가 답변에 새 근거가 오면 원장에 신규 ID만 추가하고 미완료 단계부터 이어갑니다. 기존 사실을 정정해야 하면 새 실행으로 시작합니다.

## GLM에 작업 한 번을 넘길 때

Codex가 최신 인계 MD와 다음 한 과제만 준비합니다. 아래 자리표시자를 실제 허용 경로·명령으로 채웁니다. 환경 준비·기계적인 코드 교체·전체 프로젝트 요약을 GLM에 맡기지 않습니다.

```text
목표: <현재 단계 한 개와 확인할 능력>
인계: <최신 MD의 지정 범위>
읽기: <현재 단계 지침·입력·context의 필요한 원장만>
수정 허용: <현재 입력 파일 한 개>
실행: <현재 과제에 필요한 준비된 명령>
완료 조건: <원장·내용·실제 검사 증거와 남은 미확인>
회사 제약: 지정된 열린 문서 COM만 사용. 자동 캡처·look_at·보호 Office 직접 읽기·새 연결 금지.

토큰 절약 모드로 이번에 지정한 과제 하나만 수행하세요. 필수 지침과 지정한 파일의 필요한 범위만 읽고, 전체 저장소 탐색·전체 대화/로그 재독·이미 완료한 분석 반복을 피하세요. 큰 파일은 검색한 뒤 관련 부분만 읽고, 도구 출력은 필요한 오류·수치·변경 부분으로 제한하세요. 코드는 파일로 저장하고 대화에 전문을 다시 출력하지 마세요. 변경에 필요한 검증은 생략하지 말고, 통과한 검사는 새 변경이나 실패 근거가 있을 때만 반복하세요. 동일 오류를 근거 없이 재시도하지 말고 원인과 마지막 상태를 남기세요. 완료 시 변경 파일·검증 결과·미확인 사항·다음 작업을 체크포인트에 짧게 추가하고 5줄 이내로 보고한 뒤 멈추세요.
```

독립 과제는 새 세션으로 시작하고 Codex가 전후 인계·실제 사용량·검수 결과를 기록합니다. 최종 답변 한 번을 받은 뒤 추가 GLM 요청은 새 사용자 진행 지시까지 멈춥니다. 새 세션의 절감량을 계측 없이 보장하지 않습니다.
