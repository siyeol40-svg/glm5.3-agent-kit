# 원인 분석 · 위치와 근거 연결 V9

[빈 양식](../../assets/stage-inputs/v9/cause.json)으로 `layout_profile:"reference-v9"`를 선택합니다. 기존 순서인 구성/bullets, 근거/table, 원인 또는 확인 절차/bullets, 범위/bullets를 유지합니다. 근거 표는 두 열에 2~5행입니다. 전체 본문은 서로 다른 정보 최소 15개입니다.

- `visuals.kind`는 `evidence_path`입니다. `locations`에는 짧은 설비·구간명 `label`과 그 이름이 그대로 쓰인 표의 `evidence_row`를 넣습니다. 서로 다른 이름 2~3개, 표 행 번호는 0부터 시작합니다. 같은 행에 여러 위치가 실제로 쓰여 있으면 같은 번호를 쓸 수 있습니다.
- `causal_order`에는 원인 또는 확인 절차 문장의 실제 순서를 0부터 세어 2~3개의 서로 다른 번호로 지정합니다. 해당 `line_states`는 모두 `supported`여야 합니다. 출처로 선후 또는 인과 연결이 확인된 단계만 고릅니다. 검증 조건은 해당 단계의 설명이나 근거 표에 둡니다. 가설·위험·적용 범위는 화살표에서 분리합니다. V6의 `statement_links`는 이 틀에서 쓰지 않습니다.
- 이 도해는 위치와 근거의 연결입니다. 시설 실측 도면이나 배관·유로·물리적 순서로 쓰지 않습니다. 일반 점검 절차는 일반 원리로 표시하고 특정 현장의 고장 원인이나 검증 실적과 구분합니다.
- 근거 표의 제목과 행 이름에서 현장 관측, 일반 기준, 검증 조건을 구분합니다. 범위가 다른 값은 동일한 비교로 강조하지 않습니다. 현장 원인이 확인되지 않았으면 제목에는 자료가 뒷받침하는 구조나 확인 지점을 쓰고, 결론에는 판단에 필요한 근거 또는 확인 경계를 씁니다. 시급성은 시점 근거가 있을 때만 제목에 씁니다.

## 수냉식 Plant 일반 원리

냉수 공급과 응축수 방열의 회로를 설명할 공개 또는 제공 근거가 있으면 [수냉식 Plant 빈 양식](../../assets/stage-inputs/v9/cause-cooling.json)을 사용합니다.

- `visuals.kind`는 `water_cooled_plant`, `scope`는 `general_principle`입니다. 실제 배관·계측기 위치·Pump 대수를 이 도해로 주장하지 않습니다.
- `visuals.source_id`에는 두 회로의 일반 원리를 직접 뒷받침하는 원장 ID 하나를 넣습니다. 같은 ID를 단계와 `system` 패널의 `source_ids`에도 넣습니다.
- `locations`에는 `chiller`, `pump`, `tower`를 한 번씩 씁니다. `label`은 각각 Chiller, Water Pump, Cooling Tower처럼 실제 설비 유형을 뜻하며, 이름이 쓰인 서로 다른 `evidence_row`를 연결합니다. Pump 표지는 회로별 순환 장비군을 뜻합니다.
- `causal_order`에는 일반 계측 또는 판정의 순서를 지정합니다. 설비 사이의 고장 인과를 추정하거나 이 순서를 특정 시설의 완료 실적으로 바꾸지 않습니다. 냉수와 응축수의 일반 순환은 별도로 그립니다.

해당 자료와 현재 단계만 읽습니다. 수치·조건·출처·한국어와 English 용어를 보존합니다. 자동 줄이기, 자유 좌표, 사진, 캡처, 새 연결은 사용하지 않습니다. 회사에서는 열린 지정 PowerPoint의 COM 검사만 사용합니다. 해당 구조에 맞지 않으면 [V6 구조·근거 틀](../v6/cause.md)을 검토합니다.
