# 문제 현상 · 절차와 근거 표

사실 ID가 붙은 근거 목록이 있고 일반 절차를 네 단계로 보여줄 때 [작성 양식](../../assets/stage-inputs/v5/problem-procedure-brief.json)을 씁니다. 양식의 값만 채워 새 JSON에 저장합니다. 도구가 절차·도해·출처 연결과 준비된 출처 표기를 넣습니다.

- `title`은 현상의 핵심을 한 줄로 씁니다. 페이지 번호와 ‘문제 현상’ 표제는 자동입니다. 표시 수치와 등록 식별자는 제목·표·본문 모두 `[[ID]]`를 씁니다. 단위와 비교 조건은 원장의 표시값을 따릅니다.
- `baseline`·`observed`는 각 세 항목 `[사실ID, 문구]`입니다. 열 제목은 실제 비교 관계로 짓고, 각 `focus`에는 강조할 항목의 인덱스 0~2를 넣습니다. 수치의 직접 비교는 집계 범위·단위·기간·측정 조건이 맞을 때 사용합니다. 현장 총계와 일반 적용 기준처럼 범위가 다르면 적용 기준은 `table`에 두고, 강조 칸은 확인된 현장 조건과 대응 요구에 씁니다. 적용 여부는 현장 근거로 확인한 조건까지만 씁니다.
- `procedure` 네 행은 `[사실ID, 짧은 제목, 설명]`, `table` 네 행은 `[사실ID, 지표명, 값·조건]`입니다. 절차가 일반 기준이면 영역 제목에 표시합니다. 번호는 선후가 확인된 조치에 붙이고, 보고서의 검증 조건은 해당 단계의 설명이나 근거 표에 둡니다.
- `impact`는 묶음 두 개에 각 두 항목 `[사실ID, 문구]`입니다. `supported`는 근거가 있는 내용, `risk`는 근거가 있는 가능성에 씁니다. 총 18개 행에 서로 다른 사실 ID를 쓰고, 같은 수치는 본문 한 행에 둡니다. 미확인 사항은 필요하면 부제나 결론에 밝히고 분량에 넣지 않습니다.
- 영역 제목은 근거가 답하는 내용을 씁니다. 시급성을 담은 제목에는 시점 근거가 필요합니다. 시점 근거가 없는 제도 자료는 ‘제도 대응과 운영 의무’처럼 내용을 표시합니다. `takeaway`에는 근거로 답할 수 있는 판단이나 남은 확인 범위를 씁니다.

한 줄 목표는 아래와 같습니다. 수치는 치환해 보이는 값으로 셉니다. 혼합 문장은 한글 글자 1개를 기준으로 영문 대문자 0.7, 소문자·숫자 0.6, 공백 0.4 정도로 잡습니다. 절차 제목은 ‘시설 등록’처럼 쓰고, 설명은 핵심 조건 하나를 남깁니다.

| 칸 | 한글 기준 약 |
|---|---:|
| 페이지 제목 | 29자 |
| 영역 제목 · 비교 열 제목 | 27자 · 16자 |
| 비교 강조 · 일반 항목 | 12자 · 17자 |
| 절차 제목 · 설명 | 7자 · 18자 |
| 표 지표명 · 값/조건 | 9자 · 28자 |
| 영향 묶음 제목 · 항목 | 7자 · 18자 |

대상 문서에 붙이기 전에 `Invoke-Proposal.ps1 -Action prepare-problem -RunDir <실행 폴더> -BriefPath <작성 JSON> -FactsPath <사실 ID 목록 JSON> -SourceCaption '<확인된 출처 표기>'`로 검사하고 변환합니다. 사실 ID 목록은 `[{ "id": "F1", "source_ids": ["S1"] }]` 형태로 기존 Case 출처를 연결합니다. 준비자가 자료 확인 단계에서 출처 표기를 정하고 이 명령에 넣습니다. 통과한 경우에만 빈 `stages/problem.json`이 채워집니다. 실패하면 결과를 보존하고 근거 또는 문구를 검토합니다. `text_fit`은 글자가 넘친 칸의 이름과 필요/가능 줄 수입니다. 실제 제작과 COM 검사는 이후 단계에서 수행합니다.
