# 자료 확인과 실행 시작

**입력:** 짧은 업무 요청, 보유 자료, 가능하면 대상과 현상을 알게 된 근거. **결과:** 출처 원장·수치 원장·단계별 내용·필요한 질문.

대상/관찰 현상/근거가 부족하면 필요한 것만 한 묶음으로 묻습니다. 선택 사진·정확한 횟수가 없다고 전체 작업을 포기하지 않습니다. 없음·미공개·미확인·실제 측정값 영은 다릅니다. 평가 기준이 없으면 임의 점수를 만들지 않습니다.

도구는 입력된 출처·원장 연결을 검사하며 URL 본문을 자동 확보·대조하지 않습니다. 링크만 있으면 기존 허용 수단으로 본문을 확인하거나 필요한 내용을 요청합니다. 연결 사전 점검 성공은 자료의 사실성·파일 쓰기·편집·저장 성공이 아닙니다.

모델이 사용자 자료를 Case JSON으로 정리합니다. 최초 Case·현재 단계 입력을 작성할 때 [최소 입력](v4/input.md)만 읽습니다. 출처·수치 원장과 `problem,cause,actions,effects,rollout` 순서의 ID를 준비하고 미래 단계 내용은 비워 둡니다. 처음부터 모든 페이지 내용을 작성하지 않습니다.

새 실행은 현재 단계의 01~05 진입 파일에서 profile을 선택합니다. 문제 현상은 V5, 개선 사항은 현재 진입 파일에서 V8 넓은 카드 또는 기존 V6 지원 범위를 확인하며 원인 분석·효과 파악·횡전개는 V7의 검증된 표현과 근거가 맞을 때만 V7을 사용합니다. 맞지 않으면 해당 진입 파일의 V6 지원 범위를 확인합니다. 기존 실행은 context의 profile과 기존 입력을 유지합니다. 현재 leaf 하나만 읽고 패널 순서·개수를 지킵니다. 사진 없이도 지원하는 native 도형과 문구로 구성할 수 있지만 시간·정상 과정·이미지 근거가 없으면 그 표현을 만들지 않습니다. 자료 부족을 임의의 값·다른 profile·미지원 kind로 보충하지 않습니다.

수치는 원장에 근거와 함께 등록하고 표시 문구에는 `[[N1]]`만 씁니다. 발표값과 계산값을 구분합니다. 같은 통화/기간/단위의 합계만 지원하며 순효과·환율·회수기간을 추정하지 않습니다.

도구 실행은 `scripts/Invoke-Proposal.ps1 -Action init -RunDir <허용된 새 기록폴더> -CasePath <정리한 JSON>`입니다. 성공 후 `-Action context -RunDir <기록폴더>`로 최소 자료를 받고 현재 `stages/<id>.json` 하나만 채웁니다. 빈 현재 단계는 자료 대기로 멈추며 빈 PPT로 완료하지 않습니다. 기존 실행은 status/context로 재개하고 전체 예시·소스·과거 이력을 읽지 않습니다.

후속 답변에 새 근거·수치가 있으면 [원장 추가](v4/ledger-update.md)의 `update-ledger -LedgerPath`로 신규 ID만 추가합니다. 기존 원장을 고쳐 쓰지 않으며 정정은 새 실행으로 시작합니다.
