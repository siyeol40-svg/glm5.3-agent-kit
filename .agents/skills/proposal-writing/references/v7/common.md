# 의미별 고정 도해 V7

현재 단계 leaf와 업무 자료만 읽습니다. `reference-v7`은 일반 EDR 원리, 정해진 성과 지표 조합, 계획 Gate만 지원합니다. 문제 현상은 V5를 유지하고 개선 사항은 현재 진입 파일의 V8 넓은 카드 또는 기존 V6 지원 범위를 따릅니다. V7에 맞지 않아도 실제 자료가 V6의 해당 구성을 충족하면 그 profile을 명시적으로 선택할 수 있습니다. 근거·분량 부족은 질문하거나 미완료로 남기며 profile 변경으로 숨기지 않습니다.

`visuals`는 표현의 뜻과 본문 연결을 고르는 metadata입니다. 현재 빈 양식 하나만 복사하며, mapping의 `null`은 미지정이므로 실제 문구에 맞는 정수로 바꿉니다. 임의 필드·좌표·색·폰트를 추가하거나 큰 소스를 읽고 다시 작성하지 않습니다. 근거 없는 비교, 미만→확정값, 전망→실적, 기간 범위→전후 개선, 계획→완료의 변경은 허용하지 않습니다.

회사 표기는 [English 전문 명사·한국어 설명](../terminology.md)을 따르며 영어 형용사·수식어에도 개수 제한이 없습니다. 최소 분량은 원인15/효과15/횡전개21항목입니다. 제목·장식·중복 문구·자료 없음은 세지 않습니다. 수치는 `[[ID]]`로 원장에 연결하고 지표명·단위·부등호·전망 조건과 직접 출처를 보존합니다. 본문11.5pt/세부11pt/출처10pt 아래로 줄이거나 회전·자동축소로 밀어 넣지 않습니다.

현재 단계 `validate`로 원장·형식·의미·배치·분량·용어를 확인한 뒤, 정상 UI로 이미 열린 지정 문서의 active COM에만 `render`합니다. 보호 Office 직접 읽기·자동 Open·새 앱·새 API/MCP 연결·서버를 추가하지 않습니다. 회사 자동 시각 QA·캡처·이미지/PDF export·화면 렌더·look_at은 지원하지 않습니다. COM 수치 검사를 실제 화면 검수로 보고하지 않습니다.

업무 PPT와 제작 입력에는 평가점수·QA 의견·검수 이미지·수정 정답을 넣지 않습니다. 디자인98점은 개발 목표이며 달성 사실이 아닙니다. 개인 개발 시각 검수, GLM 실사용, 회사 호환은 각각의 증거로 구분해 보고합니다.
