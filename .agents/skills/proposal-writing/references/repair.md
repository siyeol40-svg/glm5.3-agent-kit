# 기존 객체를 제자리에서 복원

제작된 관리 슬라이드의 위치·서식·문구가 정해진 원본과 달라져 실제 QA가 실패했을 때만 읽습니다. 새 내용을 넣는 기능이 아니며, 기록 파일을 편집해 통과로 바꾸지 않습니다.

**입력:** 현재 실행 기록·현재 검증된 단계 입력·지정된 열린 작업 문서. **동작:** 기존 관리 객체를 같은 입력과 고정 배치로 복원. **결과:** 같은 슬라이드의 실제 COM QA와 기록.

```text
scripts/Invoke-Proposal.ps1 -Action repair -RunDir <기록폴더> -StageId <단계ID> -TargetName <열린작업문서명>
```

- stage 상태는 `complete` 또는 현재 단계의 `failed`이며 slide_id 기록이 있어야 합니다. 해당 run/stage의 슬라이드가 유일하며 현재 입력의 content_hash·지원 layout revision·생성 COMPLETE 태그가 맞아야 합니다.
- 복원 전 객체 개수·정확한 이름·종류·역할·부모를 모두 확인합니다. 텍스트 상자·사각형·선 같은 지원 native 객체만 같은 자리에서 고칩니다. 그림/그룹/OLE, 누락·추가 객체, 소유 관계가 불명확한 슬라이드는 범위 밖입니다.
- 새 도형을 추가하거나 삭제하지 않습니다. source·원장·단계 내용 변경은 이 기능으로 처리하지 않으며 새 실행을 준비합니다. state.json·태그·hash를 손으로 바꾸지 않습니다.

수정 중에는 INCOMPLETE로 표시합니다. 예외가 나면 이 상태를 유지하고 멈춥니다. 자동 재시도나 추측한 부분 복원은 하지 않습니다. 복원이 끝나도 helper 실행 성공만으로 통과라고 하지 않으며, 도구의 실제 QA 결과를 확인합니다. 실패·확인불가는 다음 단계로 넘기지 않습니다. 화면·미학을 확인했다는 뜻도 아닙니다.
