# 횡전개 · 대상과 판정 조건

[공통 규칙](common.md) 뒤 `assets/stage-inputs/v6/rollout.json`을 채웁니다. coverage/table → expansion/flow → checks/bullets → acceptance/bullets 네 패널 순서입니다. 최소21항목입니다. 표 다섯 행·흐름 네 단계·시험 여섯 문장·판정 여섯 문장을 지원합니다. 하단 문장은 가급적 한 줄로 씁니다.

실제 적용 기록이 없으면 scope=proposal로 하고 제목·부제에 검토안/실적 아님을 명시합니다. 표에는 가짜 Line 현황 대신 검토 대상과 확인 요건을 넣습니다. 확인할 측정 항목, 시험 방법, 적용/보류 판단을 구체적으로 나눕니다. 새 기준값·완료 대수·날짜·성과는 만들어 넣지 않습니다.

검토안은 고객사가 실행한 조치가 아닙니다. 실제 실적 scope=actual은 모든 패널의 rollout_record 근거가 있어야 합니다. 기존 사례 한 건의 성과를 미검증 설비 전체에 곱하지 않습니다. 결과를 다음 제안에 쓸 때 현재 조건과 실적을 다시 확인합니다.

도구가 scope에 맞춰 ‘검토안·적용 실적 아님’ 표식을 부제 앞에 자동으로 붙입니다. 입력 subtitle은 그 문구를 반복하지 말고 이 페이지의 업무 목적·조건을 씁니다.
