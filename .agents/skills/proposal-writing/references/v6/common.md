# 조밀한 고정 틀 공통 규칙

현재 단계만 읽고 `layout_profile:"reference-v6"`와 해당 빈 양식 하나를 사용합니다. 문제 현상은 별도 V5 복합 틀입니다. 좌표·색·폰트·지원 밖 키를 입력하거나 대형 소스를 다시 작성하지 않습니다.

본문은 실제 근거와 조건을 짧게 씁니다. 제목·사진·장식·같은 지표 반복·순수 자료 없음은 분량에 포함되지 않습니다. 최소 원인15/조치18/효과15/횡전개21항목입니다. 부족하면 근거를 요청하거나 미완료로 남깁니다. 단계 역할을 바꾸거나 가설을 사실로 바꿔 채우지 않습니다.

기존 원장·출처 규칙을 유지합니다. 숫자는 `[[ID]]`, 숫자가 있는 모델명은 등록 식별자로 연결합니다. 표 숫자 셀은 정확히 한 바인딩, 행 이름은 그 지표명과 일치해야 합니다. `미만/초과` 조건을 `이하/이상`이나 확정값으로 바꾸지 않습니다. 예상 수명은 지표명과 문장에 ‘예상’을 남깁니다. 숫자를 쓰는 단계/패널의 source_ids에 해당 원문을 포함합니다.

bullets는 한~여섯 문장, flow는 두~네 단계, table은 두~네 열/한~다섯 행, metrics는 한~세 지표입니다. 각 kind의 본문 필드만 사용합니다. `outcome`은 조치 카드에만 넣습니다. 원인 causal/bullets와 효과 details/bullets의 line_states는 supported(근거 있음)/hypothesis(가설)/boundary(적용 범위)/unknown(미확인)을 구분합니다.

정해진 영역을 넘으면 TEXT_NEEDS_SHORTEN으로 중단합니다. 뜻·조건·출처를 보존해 문구를 다듬고 validate합니다. 자동축소/회전/임의 배치로 해결하지 않습니다. validate→지정 열린 문서 render→COM 재조회 순서이며, 회사 자동 시각QA·캡처·export·look_at·Office 직접 읽기·새 연결을 추가하지 않습니다. 제작 입력에는 검수 이미지/점수/수정 정답을 넣지 않습니다.

회사 표기는 [English 전문 명사·한국어 설명](../terminology.md)을 따릅니다. source 원문은 보존하고 현재 업무 본문과 숫자 지표명만 맞춥니다.
