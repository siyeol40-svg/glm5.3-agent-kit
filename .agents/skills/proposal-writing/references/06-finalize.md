# 최종 검사와 저장

**입력:** 현재 실행 상태와 단계별 검사 기록. **결과:** 저장 상태·검사 범위·남은 한계의 짧은 보고.

`status`에서 필수 단계가 모두 완료됐는지 확인합니다. 실패·확인불가·미검사가 남았는데 전체 통과라고 보고하지 않습니다. `qa`로 현재 관리 슬라이드의 실제 원문·좌표·최소 글자 크기·자동맞춤·회전을 재조회합니다. 기하상 넘침 없음은 실제 화면의 미학·사진 의미·인쇄 충실도 보장이 아닙니다.

[분량 하한](content-density.md)도 모든 현재 단계 입력으로 다시 검사합니다. 옛 complete/QA 캐시만으로는 새 정책에 합격하지 않습니다. 한 장이라도 부족하면 완료·저장 준비로 보고하지 않으며 save가 Office 연결 전에 차단합니다.

원래 입력은 그대로인데 지원 객체의 위치·서식이 바뀌었다면 [제자리 수정](repair.md)의 조건을 확인합니다. 내용 변경이나 미완성 슬라이드를 억지로 완료시키는 용도로 쓰지 않습니다.

독립 제작에서는 최종 답변 전에 동결된 소스/배치를 유지했는지 확인합니다. 시각 검수 메모·오류 위치·수정 답을 받아 고치지 않습니다. 업무 PPT에도 검수 점수/오류 의견을 넣지 않습니다. 별도 평가는 최종 답변 뒤에만 시작하며 실패 수정본은 첫 실행 통과가 아닙니다.

사용자가 지정한 저장 경로가 있으면 `save -SavePath <경로>`를 실행합니다. 파일에 DLP가 적용되므로 보호 PPT의 디스크 bytes/hash·ZIP/XML 검사나 자동 닫기/재열기를 하지 않습니다. 저장 후 현재 COM 객체 확인을 사용자 UI 재열기 성공으로 바꾸지 않습니다.

다음 세션은 짧은 resume.md와 status/context로 재개합니다. 완료 파일·단계별 결과·실제 저장 여부·미확인 사항을 짧게 보고하고 멈춥니다. GLM으로 평가 중이라면 지시 한 번의 최종 답변 후 추가 작업/재시도는 새 사용자 지시가 있어야 합니다.

보고는 Codex의 개발/개인 COM 검증, GLM의 사용 검증, 실제 회사 호환 검증을 따로 적습니다. 자동 캡처/외부 이미지 도구로 확인하지 못한 것을 몰래 보충하지 않습니다.

추가 자료를 받아 다시 작성해야 하면 [자료 추가·재개](data-contract.md#자료-추가와-재개)를 확인하며 완료된 페이지를 임의로 덮어쓰지 않습니다.
